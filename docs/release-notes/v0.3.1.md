## Kit GEX v0.3.1

Instalação em um comando por sistema e duas correções do chat e do PATH.

### Novidades

- **Instalador de uma linha.** `scripts/install.sh` (macOS e Linux) e `scripts/install.ps1` (Windows) escolhem o binário do seu sistema e da sua arquitetura, baixam só ele e o `SHA256SUMS`, conferem o SHA-256 antes de instalar e o instalam como `gex-dev-kit`. No macOS e no Linux a pasta é `~/.local/bin`; no Windows, `%LOCALAPPDATA%\Programs\gex-dev-kit`, que entra no PATH do usuário. Não pede `sudo` e não edita seus arquivos de shell: se faltar PATH, mostra a linha pronta para copiar.
- **README novo**, com banner animado, badges por sistema, instalação por sistema, primeiro uso, receitas por tarefa e solução de problemas.

### Correções

- **PATH com várias cópias de `claude` ou `codex`.** O bloqueio agora lista todos os caminhos encontrados, para você saber quais remover. Antes só dizia "múltiplos executáveis no PATH".
- **Chat com o Core alterado.** O chat dizia "0/7 skills · alterado" e em seguida "Ainda não há Core instalado". Agora conta os arquivos que precisam de atenção e manda rodar `/doctor`.

### Para saber antes de instalar

- O instalador lê o script do repositório privado pelo `gh`. Você precisa do GitHub CLI com `gh auth login` e acesso à organização Gex-Development.
- Se você tem mais de uma cópia de `claude` ou `codex` no PATH, o kit continua bloqueando a instalação dos agentes. Deixe só uma cópia no PATH e rode de novo.
- Os binários de macOS foram exercitados. Os de Linux e Windows compilam e passam por `go vet`, mas não foram exercitados em execução. O `install.ps1` também não foi executado em Windows.
- Todos os avisos da v0.3.0 continuam valendo: plugins são código de terceiros e o `rollback` não os desfaz. Veja as [notas da v0.3.0](v0.3.0.md).

Confira `SHA256SUMS` antes de executar. Os avisos de licença das dependências estão em `THIRD_PARTY_LICENSES.txt`.
